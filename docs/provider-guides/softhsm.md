# SoftHSM Provider Guide

SoftHSM v2 acts as the default CI provider for the host adapter. Use this guide when provisioning local tokens, wiring environment variables, or debugging smoke tests that target SoftHSM.

## Environment Variables
- `SOFTHSM_LIB`: Absolute path to `libsofthsm2.so`/`.dylib`. Required by both the host adapter integration test and the Wasm `guest-smoke` component.
- `SOFTHSM2_CONF`: Path to the SoftHSM config generated by `scripts/softhsm-setup.sh` (defaults to `.softhsm-tokens/softhsm2.conf`).
- `SOFTHSM_SO_PIN` / `SOFTHSM_USER_PIN`: SO/user PINs used by setup scripts; optional overrides for automation.
- `PKCS11_USER_PIN`: Inline PIN consumed by the guest smoke test when logging in.
- `PKCS11_STATE_MECH`: Optional mechanism (decimal or `0x...`) for exercising `C_GetOperationState`/`C_SetOperationState`.

## Provisioning Steps
1. Install SoftHSM v2 and `softhsm2-util`.
2. Run `scripts/softhsm-setup.sh` to initialize a token:
   ```bash
   export SOFTHSM_TOKEN_DIR="$PWD/.softhsm-tokens"
   export SOFTHSM_LIB="/usr/local/lib/softhsm/libsofthsm2.so"
   ./scripts/softhsm-setup.sh
   ```
3. The script prints the token label, SO PIN, and user PIN. Record them if you need manual access via `softhsm2-util`.
4. Export `SOFTHSM_LIB` (and optionally `PKCS11_USER_PIN`, `PKCS11_STATE_MECH`) before running `PKCS11_WIT_ROOT=$(pwd)/wit cargo test --manifest-path host-adapter/Cargo.toml`.

## Troubleshooting
- `CKR_TOKEN_NOT_PRESENT`: Ensure `SOFTHSM2_CONF` points to the token directory produced by the setup script.
- `CKR_PIN_INCORRECT`: Confirm `PKCS11_USER_PIN` matches the user PIN defined in setup. After three failures SoftHSM reports `CKR_PIN_LOCKED` and requires SO intervention.
- `CKR_DEVICE_ERROR` during RNG tests: SoftHSM rejects `seed-random` by returning `CKR_RANDOM_SEED_NOT_SUPPORTED`; the host adapter maps this to `random-seed-not-supported`.
- No slots reported: run `softhsm2-util --show-slots` to verify token creation; re-run setup if the DB is empty.
